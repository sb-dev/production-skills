# <Domain> Production Skills Extension Pack Catalogue

**Status:** Draft  
**Version:** 0.2

## Purpose

Describe the curated Extension Packs implemented or planned for this Production Skills project and the showcase used to demonstrate each one.

The pack contract remains owned by `05-<domain>-customisation-packs-spec.md` or its domain-equivalent filename. Detailed selection, extraction and challenge evidence belongs in the owning repository's research logs.

## Catalogue rules

Every entry should define:

```text
name / slug
intended use and non-use
selection rationale and complementary catalogue contribution
core baseline and specialised behavioural difference
five-book foundation and source contributions
research records, reading limitations and qualified guidance
production grammar and pack dimensions
core skills affected and what remains stable
precedence / conflicts
showcase and exact generation prompt
actual outputs when executed
pack-specific acceptance cases and comparative evidence
research, implementation, evaluation and readiness status
installation evidence and compatibility / migration notes
```

A catalogue entry is not merely a style or genre label. It must represent materially different production behaviour. Planned entries are allowed when clearly identified; a ready-to-use claim requires measured production/evaluation and clean-installation evidence.

## Catalogue selection

Link the broader candidate pool, capability-coverage matrix and selection decisions. Explain overlap, gaps and each selected pack's marginal contribution. Do not choose a fixed number of packs because each uses five books. For existing catalogues, record retained/refined/merged/retired candidates and required migration decisions without silently replacing approved work.

#### Core-vs-pack comparison

Use the same substantive brief and comparable execution conditions for core-only and packed runs. Record core/pack revisions, exact prompts, tool/model settings where relevant, resource constraints, deviations, results and evaluator limitations. State what should materially differ and what must not regress. Do not mistake richer prompting or displayed pack metadata for improvement.

#### Reuse and production evidence

Link actual showcase artefacts and a distinct additional brief/fixture, plus observed outcomes. A prompt is not proof of execution. Preserve failed or inconclusive results; planned evidence remains labelled as planned.

#### Installation and compatibility

Record local validation and clean consumer-project installation/use separately. Note required capabilities, incompatibilities, preserved interfaces and any authorised migration decisions.

## Catalogue expansion rule

Add a new pack only when it introduces reusable specialised behaviour not adequately covered by an existing pack plus project-specific instructions. Use the same research and proof gates for later additions; revise affected evidence without rerunning unrelated completed work.

## Acceptance criteria

Research, implementation, evaluation and readiness claims match linked evidence. No planned entry is presented as a ready pack, and no catalogue change silently replaces approved pack identities, supplied books or accepted productions.
